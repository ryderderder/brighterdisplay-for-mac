# XDRLift development

Keep the implementation original and MIT compatible. Never copy GPL code and label it MIT. Preserve third-party notices and document provenance.

Build: `./scripts/build.sh`. Test: `./scripts/test.sh`. Package: `./scripts/package.sh`. Use modest compiler concurrency. `Sources/Core` contains dependency-free safety and interaction logic; `Sources/XDRLift` integrates macOS APIs.

No paid gates, telemetry, captures, automatic login agent, privileged daemon, thermal bypass, permission changes, or security bypass. Only the user grants macOS control access. Never read private keys or create signing credentials without explicit approval.

Derive gamma requests from an immutable baseline; never compound changed tables or fight another display utility. Preserve reset ownership after transient failures. Every key, repeat, slider and renderer must obey the saved cap and current headroom. Raising the cap must not increase brightness. Save only the cap, never extended brightness.

Do not replace an installed app during owner acceptance testing. Build in the project output directory and install only as an explicit step. Physical keys, lifecycle/Spaces tests, and measured luminance are distinct from unit or controller tests. Do not claim one as the other.

Release only allowlisted project files. Exclude private logs, screenshots, user preferences, credentials, and unrelated files. Audit staged content and history before publishing. Require successful CI and an accurate verification record; preview releases must state remaining hardware gaps. Repository commits never automatically ship or install a binary.
